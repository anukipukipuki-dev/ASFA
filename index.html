❓ How to use this dashboard

This tool lets the integrator team track all the documentation required to integrate the onboard ASFA Digital system into a Vectron locomotive and obtain its entry-into-service authorisation in Spain.

Project workflow

Phase 0Baseline analysis and planning: technical and regulatory baseline.
Phase 1System design and technical documentation of the onboard integration.
Phase 2Workshop verification and test-bench trials.
Phase 3On-line trials over the RFIG (track testing).
Phase 4Authorisation documentation before AESF / ERA (OSS).
Phase 5Entry into service and post-authorisation documentation.

What the statuses mean

Pending — not started.
In Progress — being drafted or prepared.
Under Review — drafted, awaiting internal or external validation.
Completed — finalized and approved.
Blocked — cannot proceed (external dependency, missing information, etc.).
Not Applicable — not required for this configuration/project.

Who owns each document

Every document carries an owner badge showing which party is actually responsible for producing it — not every deliverable in an authorisation file is written by the integrator's engineering team. Filter by owner in the toolbar, or use the "Engineering-owned" counter in the header to isolate what your team is directly on the hook for.

Regulatory basis — read this before relying on it

Each document shows the source it's based on, tagged with a confidence level:

✅ Verified the specific article/annex/table was confirmed against an official AESF, ADIF or EUR-Lex source.
📖 General reference the correct regulation is cited, but the exact clause was not independently confirmed — check it against the primary source before relying on it.
🛠 Engineering practice no single external clause mandates this exact document; it is included as sound project/engineering practice.
Important: this tracker was compiled through engineering research (including live web searches against AESF/ADIF/EUR-Lex sources), not by reading every primary document end-to-end. Treat "Verified" citations as a strong starting point and "General reference" / "Engineering practice" items as needing confirmation — always validate the final document set with AESF and a qualified rail authorisation specialist before submitting a real application.

Compendium documents

Some line items are not a single file but a bundle of several distinct documents (for example, the complete Technical File). Those cards show a "📦 Compendium" box listing every component expected inside it.

Use the sidebar to navigate between phases, the filters to find specific documents, and the export buttons to back up your progress or generate a printable report.
